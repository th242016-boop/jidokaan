## 운영 설정

기존 관리자 상품수정 화면의 `네이버 상품주소`에 각각 저장했다. 운영 DB `catalog_products.data.smartstoreUrl` 값이며, 일반 상품 URL이나 임의 UTM 주소로 치환하지 않는다. 이전 값은 네 상품 모두 빈 값이었다. 네이버에서 새 링크를 발급하면 같은 관리자 필드에서 변경한다. 카탈로그 초기화 코드는 기존 상품 데이터를 덮어쓰지 않는다.

`naverProductUrl()`을 사용하는 상품상세 구매·후기, 시뮬레이터, 장바구니 페이지/패널, 국내 체크아웃 안내가 공통 설정을 사용한다. 기본 소스 상품 배열은 운영 DB의 복제본이 아니므로, 새 환경을 복원할 때 위 네 설정도 복원해야 한다.

## 중목 연결 오류 수정

- 시뮬레이터가 항상 장목 상품을 선택하던 부분을 모델에 맞게 장목/중목으로 구분했다.
- 신규 중목 시안은 `drone-mid`로 장바구니에 담는다. 장목은 기존 `drone-custom` 유지.
- 예전 중목 장바구니가 `drone-custom`으로 저장된 경우 `partNames`의 모델을 보고 네이버 링크만 중목으로 연결한다. 기존 장바구니 값, 과거 주문, 가격/결제 데이터는 변경하지 않는다.
- 여러 상품이 담긴 장바구니의 국내 네이버 버튼은 기존처럼 첫 상품에 연결된다. 네이버 장바구니 전체를 자동 생성하는 기능은 아니다.

## 확인 범위

- 관리자 저장, 실제 공개 상품 페이지의 링크 확인.
- TypeScript 검사와 격리된 실제 Zustand store 검증: 신규 장목/중목 ID, 모델 보존, 예전 중목 링크 보정, 원본 불변, 액세서리 분리.
- 실제 구매·결제·고객 알림은 실행하지 않는다. 마케팅 링크 저장을 수수료 우대 정산 확정으로 표현하지 않는다. 실제 적용은 이후 적격 주문의 네이버 정산 내역에서 확인한다.
- 빌드 및 최종 운영 배포 식별자는 기존 Drive 인수인계 문서의 같은 날짜 추가 이력을 확인한다.
