# 주문·관리자 운영 인수인계 — 2026-10-01 갱신

## 범위와 원칙

홈페이지 디자인, 시뮬레이터 렌더링/소재, 관리자 인증, 기존 주문 상태 이름은 유지한다. 이번 변경은 해외 주문의 연락처·배송비·다국어 사전 확인·확정 디자인 저장과 관리자 상세 화면이다. 기존 주문 레코드를 일괄 수정하지 않는다. 과거에 저장되지 않은 디자인, PayPal 거래 ID·수수료, 인스타그램 정보를 추측해서 채우지 않는다.

운영 저장소: `th242016-boop/jidokaan`, Railway production/main, https://jidokaan.com . 이 문서는 코드 인수인계이며, 실제 배포 성공 여부는 Railway 배포 상태와 커밋으로 확인한다.

## 고객 주문 흐름

1. 시뮬레이터에서 모든 부위 색상과 사이즈를 선택하여 장바구니에 넣는다. 같은 사이즈라도 부위별 색상이 다르면 별도 항목으로 유지한다.
2. 연락 가능한 이메일과 전화번호를 입력한다. 주 연락 방법은 인스타그램(아이디 필수) 또는 인스타그램이 없는 고객의 이메일 중 선택한다.
3. 배송 국가·주소·도시·우편번호를 입력한다. 미국 등 필요한 국가에서는 주/도도 필수다. 실제 주소의 배송 가능성을 검증하는 시스템은 아니다.
4. 주문 전 확인 사항에 각 커스텀 상품의 확정 디자인 이미지, 부위별 색상, 사이즈·수량을 표시한다. 이미지 준비 실패나 불완전한 디자인이면 결제를 막는다.
5. 선택한 언어로 배송비 포함 여부, 관세 별도, 제작 기간, 디자인 확인을 안내하고 확인 체크를 받는다. 국가·금액·언어·상품 변경 시 확인을 초기화한다.
6. PayPal 결제 생성 전에 서버에 제작 사양·이미지·가격·연락처·안내 문구를 저장한다. 결제 완료 응답을 검증한 뒤 주문을 생성한다.

국내 네이버 주문 방식은 유지한다. 여기서 설명하는 결제 전 필수 확인과 서버 주문 검증은 본 사이트의 해외 결제에 적용된다.

## 배송비 정책

사용자가 승인한 기존 포장: **410×310×150mm, 실제 무게 1.5kg 이하**. EMS 부피중량 `41×31×15/6000=3.1775kg`, 청구 구간 **3.5kg**. 한 켤레당 한 상자, 여러 켤레는 개별 포장 비용을 합산한다. 도시별 임의 할증을 만들지 않는다.

공식 비서류 EMS 요금(2026-07-01 시행)을 국가별 원가로 사용한다. 2026-10-01 배송비 부족 우려에 따라 단순 환산을 아래 책정 방식으로 변경했다. 이전 1,380원 단순 환산 정책은 신규 견적에 사용하지 않는다.

- 기준 환율 **1 USD = 1,350 KRW**. 관리자가 정하는 책정 기준이며 실시간 환율 연동이 아니다.
- 환율 하락 대비 **5%**, 결제·환전 차감 대비 **8%**, 운임 변동 여유 **3%**, **1 USD 단위 올림**.
- 공식: `ceil(운송원가KRW × 1.03 ÷ (1350 × 0.95 × 0.92))`. 8%를 단순 가산하지 않고 차감 후 잔액을 기준으로 역산한다.
- 이 비율들은 운영 준비금 가정이며 실제 PayPal 계약 수수료 또는 실제 환전율이 아니다. 상품 대금 전체에 대한 수수료/건당 고정 수수료를 배송비에 다시 전부 전가하지 않는다. 모든 손실을 방지한다고 보장하지 않는다.
- 고객에게 운송·취급 비용이 포함된 정액 요금임을 16개 언어로 안내한다. 실제 우체국 영수증과 같다고 표시하지 않는다. 관부가세는 계속 별도다.
- 관리자 배송비에서 원가·기준 환율·각 대비율·올림 단위를 바꾸면 국가별 USD와 계산 미리보기가 자동 갱신된다. 저장 이후 신규 결제 견적에 적용한다. 국가별 추가 최소 USD를 입력하면 자동 계산 금액과 비교해 더 높은 금액을 사용한다.

- 미국 96,500원 → **USD 85** (기본 설정)
- 싱가포르 30,000원 → **USD 27** (기본 설정)
- 중국 32,000원 → **USD 28** (기본 설정)
- 전체 요금표: `src/lib/ems-rates.ts`.
- 일반 EMS 요금이 없는 이탈리아·남아공은 임의의 기본 요금으로 결제하지 못하도록 별도 상담 안내. 실제 접수 가능 여부는 발송 시 우체국에서 재확인한다.
- 기존 18/28/32/38달러 및 추가 수량 40% 규칙은 해외 새 주문에 사용하지 않는다.
- `applyEmsPolicy`가 구버전 배송 설정을 읽을 때 새 정책을 적용한다. 원가가 있는 요금은 읽기/견적/저장 시 항상 재계산하여 환율만 바꾸고 USD를 갱신하지 않는 실수를 방지한다. 마이그레이션은 반복 적용해도 비율이 중복 가산되지 않으며 기존의 높은 수동 요금은 최소 청구액으로 보존한다. 원가 없는 기존 수동 요금은 유지하고 관리자에 대비율 미적용 경고를 표시한다. 이미 저장된 주문 및 PayPal 결제 시작 시 저장한 견적은 바꾸지 않는다.
- 고객 `/shipping` 요금표와 checkout, 서버 견적은 같은 국가별 설정을 사용한다.

상품+배송비를 이번 결제에 받는다. **관세·세금·통관 수수료는 미포함**. 미국 발송인 선납 비용은 운영자가 제작 전 예상액을 안내하고 출고 전 확정액을 별도로 받아야 한다. 이 변경은 관세 자동 계산/추가 결제 링크 발송/자동 메시지를 구현하지 않는다. HS 코드, 소재, 신고 금액, 실제 통관 고지 없이 세율을 고정하지 않는다. 다른 국가도 도착국 규정에 따른 비용을 별도 안내한다.

## 관리자 사용법

관리자 → 주문 목록에서 **주문 행, 주문번호 또는 상세보기**를 누른다.

상세 화면에는 주문 당시 확정 디자인 이미지(다운로드 가능), A–L 부위별 색상, 사이즈·성별 구분·수량, 연락 방법·이메일·인스타그램·전화, 전체 주소·도시·주/도·우편번호·국가, 상품/배송/할인/총액, PayPal 거래 ID·실제 응답의 수수료·실수령액·배송지 대조 정보가 표시된다. 고객이 확인한 언어와 안내 문구도 펼쳐 볼 수 있다.

과거 주문은 완전한 색상 정보가 저장돼 있으면 **현재 시뮬레이터 자산으로 재구성한 미리보기**라고 표시한다. 주문 당시 이미지가 없다는 사실을 구분한다. 정보가 부족하면 경고하고 저장된 사양만 표시한다. 누락된 디자인을 복원했다고 주장하지 않는다.

운영 순서: 결제·디자인·사이즈·배송지 확인 → `ready` 배송준비 → 제작 완료 → 운송사·송장 저장 → 실제 발송 후 `shipped` 발송. 송장 없는 발송 처리는 서버에서 막는다. 내부 메모와 PayPal 수수료/실수령액은 고객용 API 응답에서 제외한다. 상태 취소는 PayPal 환불을 실행하지 않는다. 송장/메모 저장만으로 고객 메시지가 발송되지 않는다. 시간은 한국시간으로 표시하며 DB 원본은 UTC다.

## 결제 무결성과 복구

- `checkout-quote.server.ts`가 상품/옵션/쿠폰/배송비를 서버 카탈로그에서 계산한다. 브라우저 금액을 신뢰하지 않는다.
- `paypal_checkout_drafts`에 전체 주문을 먼저 저장하고 PayPal 주문을 만든다. 고객 주소를 PayPal에도 명시한다.
- 단일 COMPLETED USD capture의 금액이 저장 견적과 정확히 같은지 검증한다. 수수료/실수령은 PayPal에서 받은 값만 저장한다.
- PayPal ID 유일 인덱스로 중복 저장을 방지한다. 재시도는 기존 주문을 반환하며 기존 상태/디자인을 덮어쓰지 않는다.
- 결제 후 DB 저장이 실패하면 관리자의 “결제 확인·주문 복구”가 PayPal 상태 조회만 수행하여 이미 결제된 주문을 저장한다. 미결제 건을 추가 청구하지 않는다. 30일 이내 최근 100개 미완료 시도를 조회하며 미결제 이탈도 포함한다.
- 결제 전 스냅샷이 없는 오래된 브라우저의 신규 결제 생성/캡처는 새로고침 안내로 차단한다. 이미 저장된 과거 주문은 계속 조회한다. 스냅샷 없는 과거 미저장 결제는 자동 복구 대상이 아니므로 PayPal 거래와 고객 정보를 수동 대조한다.
- 실제 주문 ID를 받기 전에는 성공 화면을 표시하지 않는다. 실패 시 장바구니와 세션 재시도 참조를 유지한다.
- 웹훅/자동 대사 작업은 구현하지 않았고 복구는 수동이다. 무통장 주문은 별도 클라이언트 멱등 키가 아직 없다.

## 검증

`node scripts/order-smoke.mjs` / `npm run typecheck` / `NITRO_PRESET=node-server npm run build`.

회귀 검증은 임시 PGlite DB만 사용하며 모든 실제 네트워크 요청을 차단하고 PayPal 응답을 모의 처리한다. 기존 주문 보존, 관리자 인증, 중복 결제 ID, 송장 가드, EMS 계산, 국가 미확정 차단, 언어 문구 누락, 이메일 대안, 동의/전체 디자인 검증, 다른 디자인의 장바구니 분리, 저장 실패와 추가 청구 없는 복구를 확인한다.

실제 결제/환불/고객 연락/운영 테스트 주문은 실행하지 않는다. 모의 검증을 PayPal 실제 결제 검증이라고 표현하지 않는다. 관리자 자격 증명을 채팅으로 요청하거나 테스트를 위해 인증을 재설정하지 않는다.

## 2026-10-01 변경 검증과 보존 범위

환율 하락/정산 차감 가정에서 운임+3% 잔액 확보, 국가별 정수 올림, 설정 변경 후 서버/고객 견적 일치, 구버전 이행의 반복 안전성과 높은 수동 금액 보존, 유효하지 않은 설정 차단을 회귀 검증에 추가했다. 기존 248 USD 주문과 저장된 PayPal 견적은 그대로 유지한다. 새 주문 약관 버전은 `2026-10-01-shipping-buffer-v2`이며 구형 주문 화면은 새로고침과 재확인을 요구한다.

PayPal 표준 해외 수취 요금 확인 출처: https://www.paypal.com/kr/business/paypal-business-fees (확인 2026-10-01). 표준 4.4% 및 USD 건당 0.30과 별도 환전 조건이 있으나, 운영자의 계정별 실제 조건은 거래 내역에서 확인해야 한다. 코드의 8% 준비금과 실제 수수료를 동일시하지 않는다.

## 2026-10-01 모바일 동의 체크 수정

동의 체크박스의 `disabled={!previewsReady || !quote.available}` 조건 때문에 디자인 이미지 처리 중/실패 또는 미확정 배송 국가에서 체크 자체가 반응하지 않았다. 동의 입력은 항상 조작 가능한 기본 HTML 체크박스로 두고 문구 전체를 연결했다. 체크 표시를 24px로 키우고 전체 동의 영역에 충분한 높이와 터치/키보드 포커스 표시를 적용했다.

결제 활성화 조건은 여전히 동의 + 확정 디자인 이미지 + 배송 국가 + 확정 배송비이다. 디자인 누락/실패/준비 중, 국가 미선택, 별도 배송 상담 사유를 동의 영역 바로 아래에서도 안내하며 필요한 재시도 또는 시뮬레이터 링크를 표시한다. 이미지 준비 실패를 무시하고 결제하는 변경이 아니다.

디자인 캡처는 1개 디자인/1개 레이어씩 순서대로 합성하고 각 이미지 참조와 캔버스를 정리한다. 장바구니 변경/화면 이탈 시 이전 작업을 중단한다. 디자인별 전체 대기 한도는 60초이며, 1000px JPEG가 주문 크기 제한을 넘으면 품질 0.90→0.85→0.80 순으로 조절한다. 원본 레이어·색상·좌표·합성 순서는 유지한다.

`node scripts/design-preview-smoke.mjs`: 가짜 이미지·캔버스로 합성 순서/좌표, 동시 보유 제한, 용량 초과 대응, 오류 후 재시도, 취소, 타임아웃, 캔버스 오류 시 정리를 확인한다. 실제 휴대폰 브라우저의 터치·시각 검증과 구분한다. 이 작업 당시 확인용 브라우저에서 jidokaan.com 접속이 제한되어 실제 사용자 단말의 증상 원인까지 확정한 것은 아니다.

## 2026-10-01 선택 언어 유지 수정

`LocaleSync`가 React의 초기 서버/하이드레이션 스냅샷(`ko`, `localePicked: false`)을 기준으로 자동 감지를 실행하면, 브라우저에 이미 저장된 영어 선택이 한국어로 덮어써질 수 있었다. `src/lib/locale-preference.ts`에서 동기화 시점의 실제 Zustand 상태를 읽고, 명시적인 URL 언어 → 저장된 선택 → 최초 방문 자동 감지 순으로 적용한다. 배송지와 통화는 언어 링크만으로 변경하지 않는다.

메인 화면의 시뮬레이터 진입 링크에 `?lang=en` 등 선택 언어를 전달하고 `/customize`에서 지원 언어만 검증해 적용한다. 전체 문서 이동이나 저장 공간 사용 제한에도 이 진입 경로는 언어를 전달한다. 이후 주문 화면은 같은 저장 상태를 사용한다. 시뮬레이터의 기존 번역 버튼·주문 안내를 유지하며 상품 디자인, 장바구니, 결제 금액 또는 기존 주문 데이터는 변경하지 않는다.

`node scripts/locale-smoke.mjs`: 실제 저장 모듈에 영어 저장 상태와 한국어 초기 스냅샷을 구성해 회귀를 재현하고, 수동 선택 15개 언어 우선, URL 선택, 최초 방문 자동 감지, 유효하지 않은 값 거부, 영어 버튼/주문 안내, 메인 진입 링크 전달을 확인한다. 격리된 코드 검증이며 실제 모바일 브라우저의 시각·터치 확인은 아니다.
